# The Audit Monkey MCP server

This repository includes an **owner-authored, standards-based MCP implementation**. That description does not mean OpenAI, Anthropic, Google, Cursor or Meta has certified, approved or listed it. No provider submission or deployment has been performed.

The browser app remains static and browser-only. MCP is a separately launched Node process using the same typed engine. It does not read browser storage, save cases, scan local files, contact carriers or make outbound requests. Guide reads use a fixed allowlist bundled in this repository. Input and output are visible to the connected AI client; its provider may process or retain them under its terms. The web app’s local privacy promise does not cover an AI conversation.

## Run

Use Node 22.13+ or 24+, and install at the repository root:

```sh
npm ci
npm run mcp:stdio
```

Stdout contains MCP JSON-RPC only. Launching it in a terminal waits for a client; that is expected. A client should launch the process directly using the config below.

```sh
npm run mcp:http
```

The optional HTTP test transport binds **127.0.0.1:4318 only**, at `/mcp`. It uses stateless Streamable HTTP with JSON responses, validates Host/Origin, caps request bodies at 1 MiB and returns `Cache-Control: no-store`. GET and DELETE return 405 because this implementation does not use a standalone SSE stream or persistent sessions. Do not expose this development endpoint publicly. It has no user authentication, rate limiting or production TLS termination. It is not a hosted ChatGPT/Meta connector.

## Tools, resources and prompts

| Tool | What it does |
| --- | --- |
| `calculate_wc` | WC exposure, OT premium, verified officer limits/exemptions, verified insured-sub reversal, mod periods, ordered premium elements and balance |
| `calculate_gl` | Payroll / sales / sub-cost / unit bases, verified exclusions, explicit denominator and premium elements |
| `review_case` | Input gaps, standalone adjustment estimates and carrier-versus-proposed reconciliation |
| `draft_dispute_packet` | Text-only draft cover letter, evidence index, worksheet and requests; never submits |
| `list_audit_checklist` | Required records, who to ask and why they matter |
| `get_state_rules` | Florida verification notes and source links; no invented values |
| `search` / `fetch` | Search and retrieve bundled public guides with IDs and repository citations |

All eight tools declare read-only, non-destructive, idempotent, closed-world annotations. Those hints describe the server’s behavior; they do not substitute for client consent or the provider’s own security review. Calculation tools publish typed structured results. Missing verification withholds final premium. Tool descriptions distinguish draft generation from an external action.

Seven `audit-monkey://guides/...` resources expose public guidance. `prepare_audit` is a reusable prompt. No resources expose customer files. Unknown guide IDs and arbitrary paths/URLs are rejected. Case strings are untrusted data; prompts instruct clients not to obey embedded instructions. Clients remain responsible for prompt-injection defenses.

Schemas are shared in `app/src/schema.ts`. Required keys and bounds are discoverable through `tools/list`; example data is generated by `app/src/cases.ts` and is entirely fictional. `elementsVerified` confirms the complete premium sequence; a true flag is an assertion by the caller, not independent insurance approval.

## Connect local clients

Replace `ABSOLUTE_REPO_PATH` and, if necessary, `node` with their real absolute paths. No client config is installed or changed automatically.

**Cursor** — merge this into `.cursor/mcp.json` or the client’s user MCP configuration:

```json
{
  "mcpServers": {
    "audit-monkey": {
      "type": "stdio",
      "command": "node",
      "args": ["ABSOLUTE_REPO_PATH/node_modules/tsx/dist/cli.mjs", "ABSOLUTE_REPO_PATH/mcp/server.ts"]
    }
  }
}
```

**Claude Desktop** — use the same `mcpServers` entry in the client’s documented config file, omitting `type` if the installed client expects only `command` / `args`. For reliable module resolution use the absolute runner paths below instead of depending on the client’s working directory:

```json
{
  "mcpServers": {
    "audit-monkey": {
      "command": "node",
      "args": ["ABSOLUTE_REPO_PATH/node_modules/tsx/dist/cli.mjs", "ABSOLUTE_REPO_PATH/mcp/server.ts"]
    }
  }
}
```

**Claude Code** — its project `.mcp.json` uses the `mcpServers` shape. Use the absolute-runner entry above and approve the server in the client. Follow the current client documentation if its configuration changes.

**Gemini CLI** — merge this into the documented `settings.json`:

```json
{
  "mcpServers": {
    "audit-monkey": {
      "command": "node",
      "args": ["ABSOLUTE_REPO_PATH/node_modules/tsx/dist/cli.mjs", "ABSOLUTE_REPO_PATH/mcp/server.ts"],
      "trust": false
    }
  }
}
```

**Codex / other stdio MCP hosts** — use the same direct Node + absolute `tsx` runner arguments, preserving client approval controls. “All major AI” is a compatibility target, not a promise that every consumer chat surface supports custom MCP. Model names alone do not determine MCP support; the host client does.

### Before a later hosted release

1. Decide whether to host **only public guidance** or also accept case inputs. Default to no customer-data service until its privacy and authentication design is approved.
2. Set up a real HTTPS origin, transport/proxy configuration and monitoring without logging request bodies or customer data. Update the loopback Host/Origin allowlist deliberately; do not simply expose this development process.
3. For protected data, implement the current MCP authorization standard and provider-specific OAuth discovery/flows. Add tenant isolation if persistence is ever introduced. There is no OAuth implementation or user-account system in this local release.
4. Add production request/rate limits, timeouts, abuse controls and validated payload limits at every boundary. Publish retention/deletion terms, accurate privacy and support pages and licensing terms. No fake legal/contact URLs are supplied as if already published.
5. Complete provider identity/access requirements; test initialization, discovery, tool calls, errors and cancellation in each target client using fictional data. Keep screenshots and exact versions. The automated SDK tests are not substitutes for actual product-client certification.
6. Submit only after separate deployment/publication authorization. A public MCP Registry entry, a GitHub repository and a ChatGPT/Claude/Meta listing are distinct steps. Do not call any of them “approved” before approval.
