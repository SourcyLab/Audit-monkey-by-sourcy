# Feed an audit, check it, and teach the next review

The pilot learning loop is now in **Review the audit → Feed, check & improve**. It combines source-quoted AI drafts, a human-corrected worksheet, immutable comparison records and approved tenant correction memory. The existing calculator remains a separate typed engine.

This is immediately reusable **reference memory**, not automatic fine-tuning of a foundation model. It changes the context supplied to the next review and shows scoped reminders even with AI off. It does not modify premium math, state rules, rates or the model's weights. No actual client-learning or performance improvement has been established by repository tests.

## Staff workflow

1. Read a text PDF locally using the existing PDF control, or paste a redacted audit excerpt. Scanned images still need OCR performed separately. Bring the full policy and supporting records; a worksheet alone may not establish the correct basis, class or exclusion.
2. Configure the optional OpenAI-compatible or Anthropic provider, model and your own key under **AI settings**. AI is off by default; keys stay in session memory. All manual audit tools and correction reminders remain available without AI.
3. Use **Use extracted PDF text** or enter selected text (maximum 60,000 characters). Inspect/redact it. Explicitly confirm authority to send that text and applicable tenant corrections to your chosen provider. No AI request occurs merely from opening a case or selecting a file.
4. Choose **Draft audit review with approved corrections**. The app retrieves currently approved matching lessons in your tenant, then sends their checked correction pairs plus your selected text to your provider. A source quote must occur in the selected document for every proposed row, mod, premium step and finding. Quote presence verifies only that the string exists, not that the model interpreted its meaning or numbers correctly. Unsupported values remain questions; the model must not assume zero or use a remembered carrier rate.
5. Inspect the plain-English questions, exposure table and document quotes. All proposals are unverified; an optional advanced data editor is available, but staff normally corrects values in the regular worksheet. **Stage checked draft in worksheet** explicitly replaces that line's rows/mods/premium steps/findings and resets verification. Export a backup first if needed. Check each rate, duty/class allocation, OT premium, officer limit, exemption, COI, date, denominator and premium element against your actual records. Editing the worksheet does not rewrite the stored original model draft.
6. Save the corrected worksheet from **Client cases**, then return to review and choose **Record before/after comparison snapshot**. It saves the original response, provider/model label, source-text hash, exact lesson versions used and saved corrected worksheet. The key is excluded. This is an authenticated staff-submitted snapshot, not a provider-signed attestation or automatic proof of correctness. The original draft and corrected worksheet remain separate.
7. Open **Record a checked correction for future audits**. State the original error/missed issue, the corrected finding, the supporting policy/manual/carrier source with edition/date/page, and the applicable coverage/class/date scope. Generalize/redact the lesson; do not copy client names, identifiers or policy-specific carrier rates into reusable advice. A correction may be submitted without an AI run for a manually identified mistake. The source worksheet must be saved first.
8. The correction enters the **draft** queue. The tenant owner checks the supporting authority and applicability, confirms identifiers were removed and explicitly approves tenant reuse. Nothing is promoted automatically from an AI answer, a carrier response, a benchmark score or a save. Editing an approved lesson creates a new draft revision requiring approval again. Reject or retire it to remove it from future retrieval.
9. Feed the next audit. The next request reloads current approval state and retrieves up to eight relevant lessons, scoped to Florida, WC/GL line, class codes and the complete policy period. Known topics are prioritized. Synthetic-source lessons are excluded from client-source cases. The model receives the prior error and checked correction as reference data, never as permission to override the current policy or provide missing numbers.

You can use **Show applicable approved corrections** without AI. This sends only matching scope (line, class codes, policy dates and synthetic/client origin) to the tenant backend; it does not send document text to an AI. Corrections and review records are private tenant service data, separate from optional cross-tenant training/sale permissions. They are not included in the generic aggregate sale export. Other tenants cannot retrieve them.

## Versioning and control

- Any teammate can submit a draft. Only its author or the owner can edit it; only the owner can approve/reject/retire it. Approval requires explicit source and redacted-reuse confirmations.
- Correction mutations use optimistic revisions. A stale approval cannot silently approve different content. The append-only journal records actor/status/revision/content hash. Review snapshots preserve the exact lesson contents/version actually supplied to that model request, even if current memory is later refreshed or edited.
- Backend requests recheck tenant membership/state. Recording a snapshot validates the source case revision and current lesson approval/scope; stale or withdrawn lessons require a new review. Original snapshots have no edit endpoint.
- Saved source-case deletion removes its linked review records and corrections. New review/lesson content counts against tenant storage. Journal overhead is infrastructure; withdrawing a lesson does not require growing its content allocation. Infrastructure backups/retention still need the hosted-pilot policy.
- An approval is a human assertion, not a legal determination. Free-text lessons are not automatically anonymized. Owner redaction and authority checks are necessary before reuse. No raw lesson export to buyers, model fine-tuning job or cross-tenant sharing is enabled.

## Check whether it is improving

Use held-out audits and independently reviewed references. Compare the original and corrected snapshots, record missed/extra issues and critical errors, measure total staff review time, and evaluate a later review against the reference rather than judging it by confidence or fluency. Keep the model ID, source hash and lesson versions with the run. Freeze a benchmark cohort while assessing a library version; do not use that same cohort to teach and then claim an independent test score.

The [offline benchmark](real-client-benchmark.md) measures structured math/category/timing and manual-review grades. It does not itself run this AI interpretation loop. To evaluate AI review quality, grade the captured drafts and corrected worksheets separately using the independent reference. The synthetic browser test proves only that approval affects the next request's memory context, not that a real provider or client population performs better.

A later fine-tuning release would need enough reviewed, permissioned examples, a separated evaluation set and explicit model/version evaluation. Uploading more documents alone is not training, and unchecked AI outputs must not become ground truth.

This remains an undeployed local pilot. Development-code sign-in is for fictional testing. Real identifiable client documents/live collaboration require the existing private-hosting, real email verification and operational/data-handling safeguards. [Pilot runbook](pilot-runbook.md).
